```

│  localStorage 存 JWT；fetch + Bearer 鉴权      │

                │  HTTPS
┌───────────────▼─────────────────────────────┐

                │  HTTP (localhost)

│  ├─ 中间件: JWT 鉴权 / 角色守卫 / 限流          │
│  ├─ auth.js      JWT签发/校验, 密码哈希         │
│  ├─ captcha.js   SVG 图形验证码(内存Map)        │
│  ├─ users.js     用户存储(JSON)                │
│  ├─ ratelimit.js 失败计数(滑动窗口)             │
│  ├─ store.js     会话存储(JSON) + 24h 清理      │
│  ├─ llm.js       大模型调用(StepFun 真实优先, mock 仅兜底) │
│  ├─ report.js    Markdown→HTML 报告            │
│  └─ skillLoader.js 拼接 system prompt          │
└───────────────┬─────────────────────────────┘
                │
        ┌───────┴────────┐
   JSON 文件存储         大模型 API
   (server/data/)       (StepFun 阶跃星辰 API)
```

**关键约束**：单实例常驻，JSON 文件落盘；**不使用 Pure Serverless**（临时磁盘跨调用不保活，会导致会话与限流失效）。

## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Node.js 22 + Express | v1 已用，生态成熟 |
| 鉴权 | `jsonwebtoken`（HS256） | 标准 JWT 库，1 个新增依赖 |
| 密码哈希 | Node 内置 `crypto.scrypt` | 零依赖，避免引 bcrypt 原生编译 |
| 验证码 | 自研 SVG 生成（无图像库） | 轻量、可控、无需 canvas 依赖 |
| 模型 | **StepFun 阶跃星辰** `step-3.7-flash`（OpenAI 兼容 `/chat/completions`，`Authorization: Bearer`） | 国产 API，中文友好；可选 step-1 / step-2 等更强模型 |
| 配置加载 | `dotenv` 自动载入 `server/.env`（已 gitignore，不入库） | 密钥与模型参数走环境变量 |
| 前端 | 原生 H5（HTML/CSS/JS），无构建 | 与后端解耦，便于迁小程序 |
| 存储 | JSON 文件（fs 同步写） | 数据量小、24h 删除，零运维 |
| 部署 | Nginx + 单实例 Node + pm2 | 提供 HTTPS 与 XFF |

## 5. 数据模型（JSON Schema）

### 5.1 用户 `data/users.json`
```json
{
  "users": [
    {
      "phone": "13800000000",
      "pwdHash": "<scrypt_hex>",
      "pwdSalt": "<hex>",
      "createdAt": 1727000000000,
      "expiresAt": 1727086400000,
      "usedAt": null,
      "revoked": false
    }
  ],
  "admin": {
    "phone": "13900000000",
    "pwdHash": "<scrypt_hex>",
    "pwdSalt": "<hex>"
  }
}
```
- **状态计算**（列表展示用）：`revoked` → 已作废；`usedAt===null` 且未过期 → 未使用；`usedAt!==null` → 已使用；`Date.now()>expiresAt` → 已过期。
- **admin 密码无 expiresAt**（长期有效）。

### 5.2 限流 `data/ratelimit.json`（可选持久化；默认内存 Map）
```json
{
  "byPhone": { "13800000000": [ts, ts, ts] },
  "byIp":    { "1.2.3.4":      [ts, ts] }
}
```
- 仅存失败时间戳；查询时过滤 `ts > now-24h` 计数；超过上限拒绝。

### 5.3 会话 `data/sessions/<id>.json`（沿用 v1）
含 `messages / status / report / adUnlocked(移除) / createdAt / expiresAt`，24h 清理。

## 6. 核心模块设计

### 6.1 密码生成算法 `users.js`
- **字符池**：
  - 数字池：`23456789`（排除 0、1，规避 0/O、1/l/I 混淆）
  - 字母池：`ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`（排除 I、O、l）
- **生成**：随机选取 1 个数字 + 9 个字母，整体 **Fisher–Yates 洗牌**得到 10 位字符串。
- **哈希**：`scrypt(password, salt, 64)` → 存储 `pwdHash` + `pwdSalt`。
- **有效期**：`expiresAt = createdAt + 24h`；登录成功后写入 `usedAt`，但**不延长** expiresAt（与 PRD「登录成功后 24h 失效」一致）。

### 6.2 图形验证码 `captcha.js`
- `POST /api/auth/captcha` → 返回 `{ captchaId, svg }`；答案存内存 `Map(captchaId → {answer, expireAt})`，**5 分钟过期**，过期自动清理。
- 答案：4 位非歧义字符（`23456789ABCDEFGHJKLMNPQRSTUVWXYZ`，避免大小写混淆）。
- SVG：随机基线旋转、噪点线、每字独立色相（黛蓝系），**服务端渲染、无图像库**。
- 校验：登录时提交 `captchaId + captchaInput`，大小写不敏感比对；错误只拦截本次、**不计入失败限流**。

### 6.3 鉴权 `auth.js`
- 登录成功：`jwt.sign({phone, role}, JWT_SECRET, {expiresIn:'24h'})`。
- 中间件 `requireAuth`：解析 `Authorization: Bearer`，`jwt.verify` 失败 → 401；成功挂 `req.user`。
- 守卫 `requireAdmin`：`req.user.role!=='admin'` → 403。
- **IP 获取**：`req.ip`（Express 配 `trust proxy` 后取 `X-Forwarded-For` 第一段）。

### 6.4 限流 `ratelimit.js`
- 滑动窗口：以 `(维度, key)` 为索引，存失败时间戳数组；查询时 `count = 时间戳.filter(t => now-24h < t)`。
- 维度：`byPhone(phone)` 上限 5；`byIp(ip)` 上限 10。
- 计数触发：仅「手机号或密码错误」时 `record(phone, ip)`；图形验证码错误**不记录**。
- 达上限：返回 429 + 模糊提示「尝试过多，请 24 小时后再试」。
- 实现：`module-level Map`（重启清零，攻击窗口随之重置，可接受）；如需跨重启持久化，落 `ratelimit.json`（启动载入）。

## 7. API 接口设计

### 7.1 配置
- `GET /api/config` → `{ features:{ads:false}, maxInputChars:5000, maxPostReportRounds:10, retentionHours:24 }`

### 7.2 认证与账号
| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/auth/captcha` | 无 | 获取图形验证码 `{captchaId, svg}` |
| POST | `/api/auth/login` | 无 | `{phone, captchaId, captchaInput, password}` → `{token, role}`；失败按限流+模糊提示 |
| GET | `/api/me` | 任意 token | 返回 `{phone, role}` 供前端渲染 |

### 7.3 管理后台（需 `role=admin`）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/users` | 创建用户并生成密码：`{phone}` → `{phone, password(明文,仅此次返回), expiresAt, status}` |
| GET | `/api/admin/users` | 用户列表（含状态：未使用/已使用/已过期/已作废） |
| POST | `/api/admin/users/:phone/reset` | 重新生成密码（覆盖旧 hash，重置 expiresAt/usedAt） |
| POST | `/api/admin/users/:phone/revoke` | 作废账号（`revoked=true`，登录拒绝） |
| PUT | `/api/admin/password` | admin 修改自身密码 `{oldPwd, newPwd}` |

### 7.4 诊断与会话（需任意 token；移除 /api/ad）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/session` | 新建会话（返回 `sessionId` + 首条 AI 问候） |
| GET | `/api/session/:id` | 会话元信息 + 历史 `messages`（刷新续聊） |
| POST | `/api/session/:id/message` | 发消息：`{content}`（≤5000字校验）；返回 `{reply, postReportTurnsLeft}` |
| POST | `/api/session/:id/report` | 生成报告 → `{reportMarkdown, reportReady}` |
| GET | `/api/session/:id/report/download` | 直接下载 HTML 报告（**无广告闸门**） |

### 7.5 错误码约定
| HTTP | 含义 |
|---|---|
| 400 | 参数缺失/格式错（手机号格式、字数超限） |
| 401 | 未登录 / token 失效 |
| 403 | 角色不足（访问 admin 接口的非 admin） |
| 404 | 会话/用户不存在 |
| 429 | 登录失败限流达上限 |
| 500 | 服务端/模型异常 |

## 8. 前端技术方案

### 8.1 路由与状态
- 单页五视图：`home / login / admin / chat / report`，通过 `data-go` 切换（沿用设计稿）。
- 全局状态：`token`（localStorage）、`currentSessionId`、`role`。
- 启动时若存在 token 调 `/api/me` 校验；失效则跳登录。

### 8.2 网络层 `api.js`
- 统一封装：`authFetch(url, opts)` 自动加 `Authorization: Bearer`；401 时清 token 跳登录。
- 登录流程：先 `GET captcha` 渲染 SVG → 提交登录 → 存 token → 跳 chat/home。

### 8.3 设计 token（`tokens.css`）
- CSS 变量：`--paper:#F4F0E7; --ink:#1F1E1A; --indigo:#2B3A5E;` 等；字体 `--serif:'Noto Serif SC'` / `--sans:'Noto Sans SC'`；噪点纹理（SVG 背景）。
- 组件：编辑风卡片、细黛蓝分隔线、栏目编号 01/02/03、黛蓝「罗」印、勾选框（登录页隐私协议）。

### 8.4 关键交互
- 登录页：未勾选《隐私协议》→「登录」按钮 `disabled`（`.btn:disabled` 半透明）。
- 诊断页：实时字数计数、报告后「追问剩余 N 轮」倒计时、第 11 轮禁言。
- 报告页：直接「下载报告」（无广告）。

## 9. 安全设计要点

1. **密码**：scrypt 哈希 + 随机 salt，明文不落盘；仅创建/重置时一次性返回前端。
2. **JWT**：HS256 + 强随机 `JWT_SECRET`（env）；无主动失效（PRD 接受，24h exp）。
3. **图形验证码**：服务端生成、绑定 captchaId、5min 过期、先校验再放行密码校验。
4. **限流**：手机号(5) + IP(10) 双维度滑动窗口，防爆破。
5. **防枚举**：登录失败统一提示「手机号或密码错误」。
6. **隐私**：对话/报告 24h 自动删；手机号不展示、不导出；隐私协议强制勾选。
7. **传输**：全站 HTTPS（Nginx 终止）；`X-Forwarded-For` 用于 IP 限流。

## 10. 部署方案

|---|---|
