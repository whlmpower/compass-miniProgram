## 2. 产品概述

### 2.1 产品定位
一款以「职业自我认知诊断」为核心的产品。用户通过一问一答式的对话，沿心理学维度与多个现实参照系，厘清自己在求职/职业选择中的真实矛盾，最终得到一份**属于个人的结构化诊断报告**。

### 2.2 演进历程（决策背景）
| 阶段 | 方案 | 结论 |
|---|---|---|
| 最初设想 | 微信小程序 + 微信支付（¥3.9/次） | 个人号无法开通商户号，走不通 |
| 替代变现 | 小程序内两次 10s 激励视频广告（进入诊断前、下载报告前） | 个人号同样无法开通流量主，且职业/心理类目个人主体大概率过审失败 |
| 形态调整 | 公众号 + H5 | 个人订阅号无网页授权、入口弱、无法变现，不优 |
| 当前决策 | **独立 H5 网站**（个人主体可上线，迁移小程序后端零改动） | 先验证产品，后续办**个体工商户营业执照**（免费）解锁真实广告/支付与合规上架 |
| v2 升级 | 引入登录鉴权 + 去广告（封闭分发模式） | 见本 PRD 全文 |

### 2.3 目标用户
- **核心**：正处于职业选择路口、感到纠结（如大厂 vs 国企、外企 vs 回老家、考研 vs 工作、稳定 vs 自主）的人群。
- **准入**：本产品为**封闭分发**——用户账号由管理员统一创建并发放，不开放自助注册。

### 2.4 核心价值主张（首页唯一传达目标）
> **「这个网站能解决我的求职选择问题，看起来专业、靠谱。」**

叙事闭环：设计理念撑「专业」、诊断样例撑「能解决选择」、诊断方式 + 隐私条款撑「靠谱」。

### 2.5 对外文案原则（已确认，贯穿全站）
- **不暴露技术栈**：不向用户提及「大模型 / DeepSeek / API / 提示词」等字眼。
- 用户关心的三件事：靠不靠谱（方法论）、对我有没有用（量身）、安不安全（隐私）。

## 3. 名词与角色

| 名词 | 说明 |
|---|---|
| 管理员（admin） | 系统初始预设账号，负责创建用户、生成密码、查看用户列表。**密码长期有效**，不受 24h 限制 |
| 普通用户（user） | 由 admin 创建、线下发放账号密码，完成诊断与下载 |
| 验证码（图形） | 登录页的防机器图形验证码（SVG），与 admin 生成的「密码」是**两种完全不同的东西** |
| 密码 | admin 为用户生成的 10 位凭证（1 位数字 + 9 位字母），**登录成功后 24h 自动失效** |
| JWT | 登录成功后签发的无状态令牌，用于接口权限控制，有效期 24h |
| 会话（session） | 一次诊断对话的完整上下文，含消息、状态、报告；默认留存 24h 后自动删除 |

## 4. 功能需求

### 4.1 账号与权限体系
- **账号来源**：仅管理员创建。**无自助注册、无开放注册入口**。
- **管理员初始凭据**：写入 `.env`（已 gitignore）的 `ADMIN_PHONE` / `ADMIN_PASSWORD`，首次启动写入存储。**admin 密码长期有效**，可后续在后台修改。
- **密码生成规则**：
  - 长度 **10 位**：1 位数字（随机位置）+ 9 位大小写字母。
  - 字符集：**排除歧义字符**（0/O、1/l/I），提升可读性。
  - 生命周期：登录成功后 **24h 内可复用**；超过 24h 自动失效，需 admin 重新生成（覆盖写入）。
  - **存储为哈希**（bcrypt/scrypt），绝不存明文。
- **下发方式**：admin 后台生成后页面展示 + 复制，由 admin **线下（微信/口头）告知用户**。MVP 不接短信/邮件。

### 4.2 登录认证（三要素）
- 登录要素：**手机号 + 图形验证码 + 密码**。
- **校验顺序**：先校验图形验证码（错则直接拦截，防机器刷量）→ 通过后再校验手机号 + 密码。
- **失败计数规则**：
  - 维度 1：同一手机号，24h 内最多失败 **5 次**。
  - 维度 2：同一 IP，24h 内最多失败 **10 次**。
  - 仅「手机号或密码错误」计入失败；图形验证码错误**只拦截本次、不计数**（避免误触锁定）。
  - 窗口：滑动 24h，随时间自动恢复；达上限后拒绝登录并提示「尝试过多，请 24 小时后再试」。
  - 防枚举：无论「手机号未注册」还是「密码错误」，统一提示「手机号或密码错误」。
- **JWT 签发**：
  - payload：`{ phone, role(admin|user), iat, exp }`，`exp = 登录时刻 + 24h`。
  - 前端：`localStorage` 存储，每次请求携带 `Authorization: Bearer <token>`。
  - **不做主动失效**（令牌泄漏 24h 内有效、24h 后需重登）——可接受。
- **登录页合规**：必须**勾选同意《隐私协议》**后方可登录（未勾选时登录按钮禁用）。
- **IP 获取**：取 `X-Forwarded-For`（考虑反向代理/负载均衡）。

### 4.3 首页（公开）
- 首页**公开**，无需登录即可查看理念、样例、隐私协议；点「开始诊断」跳转登录，登录后进入诊断。
- **信息架构（已重排，去重）**：
  1. **Hero**：主标题「在选择的路口，先认识自己」+ 一句话承诺。
  2. **01 设计理念**：只讲**分析框架本身**——六个心理学维度（安全感/成就感/自主/关系/意义/成长）构成价值坐标系；六个现实参照系（大厂/国企/体制内/外企/创业/考研 vs 工作）提供镜子；把纠结翻译成结构。撑「专业」。
  3. **02 诊断样例**：脱敏样例卡片（详见 4.3.1），早展示价值。撑「能解决选择」。
  4. **03 诊断方式**：只讲**体验与机制**——对话而非填表、约十几轮/十几分钟、24h 自动删除。撑「靠谱」。（已从原「技术说明」改为用户视角话术，**不暴露技术栈**。）
  5. **04 隐私与条款**：简述采集范围 + 「用完即删」原则，提供协议入口。
  6. **05 怎么开始**：从脚注提上来的**转化命门**——说明封闭分发、账号由管理员发放。
  7. **CTA**：「开始诊断」按钮 → 登录。
- **4.3.1 样例来源**：使用 `server/skill/reports/山大班长.md` 等脱敏样例，**固化复制到 `web/samples/` 展示**。`server/data/reports/`（运行时生成、被 gitignore、含测试痕迹）**不展示**。

### 4.4 诊断对话
- **权限**：需任意有效 JWT（登录后）。
- **交互**：一问一答；AI 提问基于用户上一轮回答（苏格拉底式）。
- **输入限制**：每轮用户输入 **≤ 1000 字符**（前端实时计数）。
- **报告前**：不限轮次（skill 自适应）。
- **生成报告**：提供「生成报告」按钮，用户主动触发（非模型自动、非固定轮次）。
- **报告后**：最多再追问 **10 轮**，用尽后**禁言**（禁止继续对话）。
- **续聊**：刷新页面可恢复历史消息（后端返回 messages）。

### 4.5 报告生成与下载
- **生成**：后端调用 **StepFun 阶跃星辰**大模型（默认 `step-3.7-flash`，OpenAI 兼容，真实优先；`LLM_MOCK=true` 时启用内置演示兜底）生成 Markdown，转为 HTML 报告（含打印样式），落盘 `server/data/reports/<sessionId>.html`。
- **报告阶段事实注入**：按需注入用户所选参照系对应的 `research/` 事实依据（仅注入所选一份，避免 token 膨胀）。
- **下载**：登录用户**直接下载**（v2 已**移除广告闸门**），无前置观看广告。
- **留存**：报告生成后保留 **24 小时**供重复查看/下载，超时自动删除对话 + 报告文件。

### 4.6 管理后台（用户管理 / 生成密码）
- **权限**：接口要求 `role=admin` 才放行。
- **生成密码区**：输入用户手机号 → 生成 10 位密码 → 黛蓝虚线框展示 + 复制按钮 → admin 线下发放。
- **用户列表**（含，非二期）：展示已创建账号，字段含：
  - 手机号
  - 密码状态：**未使用 / 已使用 / 已过期**
  - 生成时间 / 过期时间
  - 操作：重新生成（覆盖）、作废（可选）
- **admin 自身**：可修改自己的密码。

### 4.7 隐私与数据安全
- **隐私协议（按新模型重写）**：去掉广告 SDK 数据采集条款，改为说明：
  - 收集范围：手机号、账号密码（哈希存储）、对话内容。
  - 账号密码 **24h 有效期**；对话与报告 **24h 自动删除**，不留底稿。
- **删除机制**：服务端定时（每小时）清理超 24h 的会话 JSON 与报告 HTML。
- **合规底线**：手机号/对话属个人信息，前端不展示、不导出；仅订单/使用统计（若有）长期留存用于对账（v2 暂以使用统计为主，不含个人内容）。

## 5. 非功能需求

### 5.1 技术架构
- **前端**：原生 H5 单页（移动端优先），与后端彻底解耦（便于后续 uni-app 重写迁移小程序）。
- **后端**：Node.js + Express，REST API（JSON）。
- **大模型**：StepFun 阶跃星辰 `step-3.7-flash`（OpenAI 兼容 `/chat/completions`，`Authorization: Bearer` 鉴权），提示词源自 `hemo-career-compass` Skill（已抽取至 `server/skill/`）。密钥与模型参数经 `server/.env`（gitignore）注入。

### 5.2 存储
- **方式**：JSON 文件存储（沿用现有 `store.js` 风格，零依赖），用户/密码哈希/失败计数/会话/报告均存 JSON。
- **约束**：**单实例常驻部署**（轻量云服务器）。Pure Serverless + JSON 会失效（临时磁盘跨调用不保活），故不采用纯 Serverless。
- **抽象预留**：`store.js` 背后可平滑替换为 SQLite → 云数据库，业务接口不动。

### 5.3 安全
- 密码哈希存储；JWT 无状态、靠 exp 失效；失败限流双维度防爆破；图形验证码防机器；登录失败模糊提示防枚举；隐私协议强制勾选。

### 5.4 部署
- **轻量云服务器**（约 ¥60–120/年），单实例常驻。
- 域名 + ICP 备案（已计划）；HTTPS（免费 SSL）。
- JWT 不做主动失效。

### 5.5 性能
- 单用户诊断耗时取决于模型调用；对话与报告均在 24h 内清理，存储压力小。

## 6. 业务规则与约束汇总

| 规则 | 取值 |
|---|---|
| 密码长度 / 构成 | 10 位 = 1 数字 + 9 字母（大小写混合，排除 0/O/1/l/I） |
| 用户密码有效期 | 登录成功后 24h 自动失效 |
| admin 密码有效期 | 长期有效（不受 24h 限制） |
| JWT 有效期 | 24h |
| 失败限流 | 同手机号 24h≤5 次；同 IP 24h≤10 次 |
| 失败计数触发 | 仅手机号/密码错误（图形验证码错误不计数） |
| 每轮输入上限 | 1000 字符 |
| 报告前轮次 | 不限 |
| 报告后追问 | 最多 10 轮，之后禁言 |
| 数据留存 | 会话 + 报告 24h 自动删除 |
| 广告 | v2 已移除（进出两道闸门均取消） |
| 账号注册 | 封闭分发，仅 admin 创建 |
| 样例展示源 | `server/skill/reports/` 脱敏内容固化至 `web/samples/` |

## 7. 设计语言（已锁定，详见 `design/index.html`）

| 维度 | 取值 |
|---|---|
| 气质 | 智性编辑风（像严肃独立刊物，而非模板站） |
| 配色 | 宣纸米白 `#F4F0E7` + 墨黑 `#1F1E1A` + 黛蓝 `#2B3A5E`（唯一锐利色，仅用于印章/编号/按钮/强调） |
| 字体 | 标题思源宋体（Noto Serif SC）+ 正文思源黑体（Noto Sans SC） |
| 质感签名 | 全站宣纸噪点纹理（SVG 噪点 + multiply，约 5% 透明） |
| 动效 | 仅入场错落淡入（标题/文字逐层上浮）+ 轻量微交互（下划线展开、按钮 hover、卡片轻浮） |
| 记忆点 | 栏目编号 01/02/03 + 细黛蓝分隔线；黛蓝「罗」印品牌标记 |

**五视图设计重点**：
1. 首页：刊物式栏目编号、大衬线 Hero、样例卡片、隐私协议弹层。
2. 登录：三要素 + 隐私协议勾选（未勾选禁用登录）+ 模糊错误提示 + 限流说明。
3. Admin 后台：生成密码区（黛蓝虚线框展示）+ 细线用户列表（状态标签）。
4. 诊断对话：两色调气泡（AI 左纸面留白 / 用户右墨黑）、1000 字实时计数、生成报告、报告后 10 轮倒计时禁言。
5. 报告预览：正式咨询报告版式（黛蓝顶边 + 机密提示 + 六维分析进度 + 参照系对比 + 行动建议）、直接下载（无广告）、24h 删除提示。

## 8. 验收标准（Acceptance Criteria）

- [ ] 未登录访问诊断接口返回 401；admin 接口非 admin 角色返回 403。
- [ ] 登录三要素：图形验证码错误只拦截、不计数；手机号/密码错误计入限流。
- [ ] 同手机号失败 5 次（24h 内）被拒；同 IP 失败 10 次被拒；窗口滑动恢复。
- [ ] 登录页未勾选隐私协议时「登录」按钮禁用。
- [ ] 用户密码登录后 24h 失效；admin 密码长期有效。
- [ ] JWT 24h 过期后需重登。
- [ ] 首页公开可浏览；样例来自 `web/samples/`；文案不暴露技术栈。
- [ ] 诊断每轮 ≤1000 字；报告后最多 10 轮，第 11 轮禁言。
- [ ] 报告生成后直接下载（无广告）；24h 后对话 + 报告自动删除。
- [ ] Admin 可生成密码、查看用户列表（状态/过期）、重新生成/作废。
- [ ] 设计语言与设计稿 `design/index.html` 一致（配色/字体/纹理/动效）。

## 10. 风险与待办（Open Items）

1. **类目/合规风险（最高）**：职业测评/心理类目在微信小程序个人主体大概率过审失败；H5 独立站可规避类目，但个人号做测评若被举报仍可能被微信拦截。建议尽早办个体户。
2. **冷启动变现**：个人号无流量主/支付，MVP 只能免费验证；需攒 UV 或转个体户才能变现。
3. **存储形态约束**：JSON 方案依赖单实例常驻，勿用 Pure Serverless 部署。
4. **JWT 无主动失效**：令牌泄漏 24h 内有效，高风险场景后期可加黑名单（本期不做）。
5. **样例数量**：本期样例可先固化 1 篇（山大班长.md），后续扩充。
6. **admin 联系方式占位**：`05 怎么开始` 可加「账号问题请联系 XXX」占位，待填实际管理员信息。
